# Regras do projeto para agentes de desenvolvimento

## Documentação viva obrigatória
Antes de alterar código, leia `docs/README.md` e os capítulos relevantes. Toda feature, alteração de fluxo, regra de negócio, integração, permissão ou correção significativa exige atualização dos documentos correspondentes em `docs/` **no mesmo commit/PR**.

- Atualizar funcionalidades, passos de uso, dados/arquitetura, regras e operação conforme impacto.
- Atualizar pendências em `docs/08-pendencias.md` sem apresentar planejamento como código entregue.
- Registrar data, mudança, referência de código e testes efetivamente feitos em `docs/CHANGELOG.md`.
- Atualizar o índice e links relativos; preservar guias especializados do projeto.
- Não versionar tokens, valores pessoais, dados identificáveis ou planilhas reais.
- Não dizer que testes ou deploy foram executados se não foram.
- Considerar documentação parte do critério de conclusão; usar Markdown no GitHub, sem PDFs recorrentes.
